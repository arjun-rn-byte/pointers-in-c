02 / THE CONCEPT

WHAT ARE POINTERS?

Pointers are a little like variables. They look like variables and, to some extent, even behave like them—but they have a special job.

They aren't frauds either. A pointer is a special type of variable that stores the memory address of another variable.

Why are pointers useful?

So why bother keeping track of addresses? Because pointers give C a way to work directly with where data lives in memory.

  1. They allow you to access and modify a variable through its memory address.
  2. They allow functions to modify the original variables passed to them.
  3. They are essential for working with arrays and strings.
  4. They allow programmers to create dynamic data structures such as linked lists and trees.
03 / THE MODEL

THE CITY OF MEMORY

Imagine your computer's memory as a giant city. Every variable gets its own little home somewhere in that city.

And just like every home needs an address, every variable has a memory address.

The problem? Variables don't put up signboards saying "I'm over here!"

That's where pointers come in. They keep track of those addresses so C knows exactly where to look.

Meet the Three Residents

🏠 The Variable

The variable stores the actual data. 

int x = 5;

📍 The Address

The address tells us where that variable lives in memory. 

&x

🗺️ The Pointer

The pointer stores the address of another variable. Think of it as a little map leading us to the variable's house. 

int *ptr = &x;
04 / OPERATORS

THE TWO MAGIC SYMBOLS

Two symbols are going to appear again and again when working with pointers:

& — The Address-of Operator

The & operator asks:

"Where does this variable live?" 
int x = 5;

&x;

It gives us the memory address of x. In our house analogy, &x gives us the address of the house.

* — The Dereference Operator

The * operator asks:

"What's inside the house at this address?" 
int x = 5;
int *ptr = &x;

*ptr;

Dereferencing the pointer allows us to access the value stored at the address it contains.

05 / SYNTAX

GIVING C A MAP

In C, a pointer is declared using the asterisk (*) symbol. 

type *pointer_name;

For example, to declare a pointer that can point to an integer: 

int *ptr;

We can then give it the address of an integer: 

int x = 5;
int *ptr = &x;

Now ptr knows where x lives.

07 / FAILURE MODES

LOST MAPS & WRONG ADDRESSES

Pointers are powerful, but even the best map is useless if the address is missing, invalid, or points somewhere that no longer exists.

🗺️ 1. The Blank Map — Uninitialized Pointer

A pointer needs a valid address before it can be used. Declaring a pointer without giving it an address leaves it pointing to an unknown location. 

#include <stdio.h>

int main() {

    int *ptr;

    *ptr = 10;      // ❌ Dangerous!

    return 0;
}

What's wrong? ptr has not been given a valid address. It's like having a map with no destination marked on it.

🚫 2. No Destination — NULL Pointer

A NULL pointer intentionally points to no valid object. It is safe to create one, but trying to access a value through it is not. 

#include <stdio.h>

int main() {

    int *ptr = NULL;

    if (ptr == NULL) {
        printf("No valid address!\n");
    }

    return 0;
}

Here, the pointer has no destination. Before using a pointer, we can check whether it is NULL.

🏚️ 3. The House Is Gone — Dangling Pointer

A dangling pointer is a pointer that refers to an object whose lifetime has ended. 

#include <stdio.h>

int main() {

    int *ptr;

    {
        int x = 10;
        ptr = &x;
    }

    // x no longer exists here.
    // ptr is now a dangling pointer.

    return 0;
}

Think of it as keeping someone's old address after their house has been demolished. The address may still be written on your map, but the original house is gone.

🧭 4. The Map Isn't the House — ptr vs *ptr

One of the most common beginner mistakes is confusing the pointer itself with the value it points to. 

#include <stdio.h>

int main() {

    int x = 25;
    int *ptr = &x;

    printf("Address: %p\n", (void *)ptr);
    printf("Value: %d\n", *ptr);

    return 0;
}

ptr gives us the address stored in the pointer, while *ptr gives us the value at that address.

🧠 Remember:

The map isn't the house.

ptr → 📍 Where is the house?

*ptr → 🏠 What's inside the house?

🔑 Pointer Golden Rule

Before following a pointer, always make sure you know where it points.
